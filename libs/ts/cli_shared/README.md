# @openclaw/cli-shared

Shared library that turns any OpenClaw TS plugin into a standalone CLI tool — without writing per-plugin CLI code.

## What it provides

| Module | Purpose |
|--------|---------|
| `runtime.ts` | Generic CLI runner: arg parsing, help generation, output formatting, env→config mapping |
| `generate-cli.ts` | Build-time code generator: introspects `createEntry()` and emits CLI entry points |

## How it works

```
┌─────────────────────────────────────────────────────┐
│ Build time                                          │
│                                                     │
│  generate-cli imports createEntry()                 │
│       ↓                                             │
│  Calls register() to capture tool definitions       │
│       ↓                                             │
│  Emits dist/bin/<name>.js (one-liner)               │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│ Run time                                            │
│                                                     │
│  Generated file calls run(createEntry(), options)   │
│       ↓                                             │
│  run() captures tools via mock registerTool         │
│       ↓                                             │
│  Maps argv → subcommand + params                    │
│       ↓                                             │
│  Calls tool's execute() function                    │
│       ↓                                             │
│  Formats output (pretty or --json)                  │
└─────────────────────────────────────────────────────┘
```

## Installation

Add as a dev dependency in your plugin:

```json
{
  "devDependencies": {
    "@openclaw/cli-shared": "file:../../libs/ts/cli_shared"
  }
}
```

## Usage

### Build step

Add `generate-cli` to your plugin's build script:

```json
{
  "scripts": {
    "build": "tsup && generate-cli --entry ./dist/index.js --out ./dist/bin"
  }
}
```

### Running the generated CLI

```bash
# After build:
node dist/bin/stock-quotes.js --help
node dist/bin/stock-quotes.js stock-quote AAPL
node dist/bin/stock-quotes.js stock-quotes MSFT GOOGL --json
```

Or link globally via `npm link`:

```bash
npm link
stock-quotes stock-quote AAPL
```

## CLI features

### Subcommands

Each registered tool becomes a subcommand:
- `stock_quote` → `stock-quote` (underscores become hyphens)
- Plugin prefix is optional: `quote` also matches `stock_quote`
- Single-tool plugins: any positional args go to the only tool

### Positional args

Required parameters become positional arguments in schema order. Array-typed parameters consume all remaining positional args.

```bash
stock-quotes stock-quote AAPL         # Single required param
stock-quotes stock-quotes MSFT GOOGL  # Array param consumes all remaining
```

### Flags

Optional parameters become `--flag value` options:
```bash
my-plugin do-thing --format csv
```

### Output modes

| Mode | Trigger | Behavior |
|------|---------|----------|
| Pretty | Default | Formatted text output with colors/symbols |
| JSON | `--json` | Raw JSON from the tool's execute() return value |

### Help

```bash
stock-quotes --help       # Top-level help with all subcommands
stock-quotes quote --help # Subcommand-specific help (future)
```

## Environment variables (config)

When a plugin declares a `configSchema`, the runtime maps each field to an env var:

```
<ENV_PREFIX>_<FIELD_NAME_IN_SCREAMING_SNAKE>
```

**Mapping rules:**
- `envPrefix` is derived from the plugin ID: `stock-quotes` → `STOCK_QUOTES`
- camelCase fields become SCREAMING_SNAKE: `finnhubApiKey` → `FINNHUB_API_KEY`
- Full var: `STOCK_QUOTES_FINNHUB_API_KEY`

The `--help` output lists all env vars with descriptions from the schema.

## Generator CLI reference

```
generate-cli --entry <path> --out <dir>

Options:
  --entry   Path to the compiled plugin index.js (must export createEntry)
  --out     Directory to write generated CLI file(s)
```

The generator:
1. Dynamically imports the plugin entry
2. Calls `createEntry()` to get metadata (id, name, description, configSchema)
3. Derives the bin name from the plugin ID
4. Derives the env prefix from the plugin ID
5. Writes a single file: `<out>/<bin-name>.js`

## Generated file contents

The generated file is minimal (~6 lines):

```js
#!/usr/bin/env node
// Auto-generated by @openclaw/cli-shared generate-cli
// Do not edit — regenerate with: npm run build
import { run } from "@openclaw/cli-shared";
import { createEntry } from "../index.js";

run(createEntry(), { binName: "stock-quotes", envPrefix: "STOCK_QUOTES" });
```

## Future: Custom formatters (hooks)

Currently, `run()` uses a default pretty formatter. A future version will support custom formatters via hooks in `createEntry()`:

```ts
export function createEntry() {
  return {
    // ...existing fields...
    cli: {
      formatters: {
        stock_quote: (result) => `${result.symbol}  $${result.price}`,
      },
    },
  };
}
```

This will allow plugins to customize CLI output without writing full CLI shims.
